Agent exploration becomes replayable proof.

The repository is a GitHub composite action and CLI that gives an LLM a constrained browser inside E2B, records semantic actions, compiles them into a safe Playwright test, replays that test in a fresh local browser, and gates CI on three independent signals.

The trust model

A green replay alone is deliberately insufficient

PASS = the recorded plan contains a real assertion and the agent finishes “pass” and the fresh Playwright replay passes.

01

Semantic assertion

The plan must contain expectRole or expectText. Navigation-only sessions are “incomplete.”

02

Agent conclusion

The model must explicitly call finish(pass). Hitting the step cap cannot silently pass.

03

Independent replay

The generated test runs once in a fresh browser. This—not the model’s narrative—is the executable evidence.

Distribution layer

action.yml resolves the preview/PR, installs the action’s dependencies and Chromium, fetches a PR diff, runs the CLI, uploads artifacts, comments on the PR, then maps the CLI exit code to CI.

CLI orchestration

bin/e2e-prove.ts coordinates sandbox setup, model selection, agent loop, session persistence, video building, deterministic replay, summary writing, and cleanup.

Agent runtime

src/agent/ wraps E2B/CDP, OpenAI and Anthropic clients, the iterative tool loop, constrained browser/terminal tools, screenshots, and exploration video.

Proof engine

src/proof/ defines the portable data contract, validates sessions and plans, renders safe Playwright source, runs the replay, collects evidence, redacts secrets, and decides the verdict.

Demo and review UI

src/components/, src/main.tsx, and server/proofmode-runtime.ts provide a local demo product, capture/review surfaces, and proof bundle visualization. They are not required by the packaged CLI.

Tests and rehearsals

Unit coverage exists for verdict gating, redaction, CLI parsing, session→plan→spec rendering, and package module resolution. A fixed low-stock Playwright test and reliability/export scripts support the demo.

Architecture review

What is solid—and what is not proven yet

Strong: constrained code generation

The model never supplies executable JavaScript. Recorded events become a validated ProofPlan; only the trusted renderer emits Playwright code. This is the central safety property.

Strong: consumer isolation

Exploration runs in E2B and replay uses the action’s pinned Playwright. Consumer dependency graphs cannot silently select a different runner version.

High: the repo does not dogfood action.yml

The current .github/workflows/proof.yml runs tests/low-stock.spec.ts directly against a fixed Vercel demo. It does not execute the E2B agent → session → replay → verdict pipeline that consumers are asked to install.

High: no cross-repo compatibility matrix

There are no external fixture repos proving preview resolution, permissions, installation, comments, and artifacts across frameworks and deployment providers.

Medium: interaction vocabulary is narrow

No select replay, checkbox-specific action, keyboard, hover, upload, download, popup/tab, iframe, shadow-root, network assertion, or mobile profile. select exists in session types but is intentionally dropped by the plan compiler.

Medium: exact replay can drift from exploration

Exploration uses role matching with exact:false; rendered replay uses Playwright’s default role-name matching. Text assertions are rendered with exact:true. These semantic differences can create replay-only failures.

Medium: operational errors collapse together

Unreachable preview, authentication, model quota, E2B startup, and agent inconclusive states do not yet have distinct product-facing statuses, limiting diagnosis and reliable CI policy.

Medium: release channel is incomplete

The package says 0.2.0, documentation recommends uses: ashish921998/e2e@v1, but the live repository currently exposes only the old proof-videos tag—not an immutable version/release tag.

Bottom line: the core proof architecture is real and thoughtfully bounded. The universal-repo claim is not yet supported by consumer-level evidence. Today’s tests mostly prove internal logic and the demo, not installation in unrelated repositories.
Recommended path

How this becomes dependable across web repos

Dogfood the published action

Replace or supplement the fixed demo workflow with a job that invokes ./ as a local composite action, then validate the exact outputs, verdict gate, comment, and artifacts.

Build external contract fixtures

Create tiny React/Vite, Next.js, Vue, static HTML, and server-rendered repos. Each should have a known-pass and known-fail PR and consume a pinned e2e action SHA.

Stabilize the portable action vocabulary

Add select/checkbox/keyboard/upload/popup/frame primitives, align exploration and replay matching semantics, and version the ProofPlan whenever its contract changes.

Introduce diagnostic outcomes

Separate product assertion failures from target, auth, sandbox, provider, model, compiler, and browser-runner failures. Preserve a single CI exit code while exposing machine-readable causes.

Publish an immutable release

Run package smoke + fixture matrix against the packed artifact, publish v0.2.0, then advance a stable v1 compatibility tag only after the matrix passes.
